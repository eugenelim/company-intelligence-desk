## Objective

The first of three specs delivering the Phase 1 agent runtime, and the one every
other guarantee is asserted against. It builds the compiler that turns an
`agent_role` record into a running agent, the four-layer toolset stack that
agent is allowed to hold, the compile-time refusals that stop a badly shaped
role from ever reaching a step, and the quarantine boundary that keeps
attacker-authored prose away from anything that can act.

Inspectability is the architecture's first-ranked quality attribute and security
of the untrusted-content boundary is its second. Both land here: the compiler is
where a role's decisions become readable, and the quarantine boundary is where
untrusted filing text stops.

Success is that a role which violates a settled design decision fails the build
rather than failing at call time; that the stack's composition is asserted by
walking the constructed chain rather than trusted; that no attacker-authored
free text reaches an agent that can act; and that the decision point this spec
puts in place refuses every call until
[`walking-skeleton-authority-containment`](../walking-skeleton-authority-containment/spec.md)
supplies its predicate. Each of those is currently a design claim with no
executable evidence.

**Its siblings.** [`walking-skeleton-foundation`](../walking-skeleton-foundation/spec.md)
is a hard dependency: it owns the schema, both append paths, the privilege split
and the pool this runs inside. [`walking-skeleton-authority-containment`](../walking-skeleton-authority-containment/spec.md)
follows this spec and supplies the decision point's predicate;
[`walking-skeleton-step-lifecycle`](../walking-skeleton-step-lifecycle/spec.md)
follows that one, because resuming a suspended step means a gated tool body
runs, and nothing can admit a call until the predicate exists.
[`walking-skeleton-evidence`](../walking-skeleton-evidence/spec.md) consumes all
three to produce the Phase 1 measurements and the browser stream.

## Boundaries

### Always do

- Treat r8 and r5 as ratified. Implement what they specify; where implementation shows one wrong, stop and say so rather than designing around it.
- Construct the agent per step, never cached across steps, because a cached agent is a cached role version.
- Record what a check does **not** establish alongside what it does.

### Ask first

- Any change to a ratified decision. The plan gives every DR decision this spec constructs a disposition, so this boundary is enforceable rather than aspirational.
- Adding a dependency beyond those in the plan's § Dependencies & integration.
- Relaxing a criterion because it is expensive to demonstrate.

### Never do

- **No typed output standing in for the deterministic parser.** Structured output is a layer; the boundary is the parser, because a control must not rest on the model's cooperation or the framework's serializer.
- **No free text crossing from a quarantined role to a planning role**, including indirectly through stored state or a resolved value.
- **No decision point that admits by default.** Until `walking-skeleton-authority-containment` supplies the predicate, every tool call is refused. The predicate arrives in a later spec; the failure direction does not wait for it.
- **No `ModelRetry` on an authorization denial.** A denial is terminal. Converting it into advice the model can retry turns the authorization boundary into a negotiation the model keeps attempting, and the interval this spec governs is exactly when nothing else asserts the exception type.
- **No `pydantic_ai` import outside `agents/` and `adapters/`.**
- **No live SEC fetch on a run's request path.** The recorded fixture is the corpus.

## Testing Strategy

Every criterion sits in exactly one group.

- **TDD (AC-0201, AC-0202, AC-0203, AC-0204, AC-0205, AC-0206, AC-0219, AC-0251, AC-0220, AC-0221, AC-0233, AC-0234, AC-0238, AC-0246, AC-0250, AC-0258, AC-0259, AC-0260, AC-0261, AC-0262, AC-0265, AC-0266, AC-0267, AC-0268, AC-0269, AC-0270, AC-0273, AC-0274)** — all of it, because all of it is a compressible invariant with a cheap oracle and no provider in the loop. The framework ships `TestModel` and `FunctionModel`, so the compiler, the toolset stack and the quarantine boundary are all exercised without a model call. Criteria are decided against four surfaces: the compiler, the constructed stack, the parser called directly, and **the loader**. The loader ones are AC-0251's `model_id` clause, AC-0262's ceiling shape, AC-0266's `trust_class` membership and AC-0273's `tools` shape on a bound row. **AC-0273's unbound-row case is the exception and is substrate**: the ratified design puts the `tools` rule on what `list_integration_tools()` reads, and states that function must read the tables, so the row no role binds is reachable only through that table read. AC-0258 and AC-0260 are **not** loader criteria: each states a compile failure, and the loader's part in them is only to supply the `pool_classes` and `tools` values the compiler then reads.

**AC-0233, AC-0261 and AC-0273's unbound-row case carry the `substrate` marker** — the first enumerates by reading both registries, where an in-memory fixture would be the suite-held list it forbids; the second reads the event log; the third is decided against `list_integration_tools()`, the whole-registry read the ratified design states must read the tables, because an unbound row is by definition absent from any one role's pinned rows. AC-0273's other three `tools` shapes stay offline on the decode seam. **A third substrate check joins the two halves of the stored role:** it inserts a role row and its pinned registry rows, reads them back through the real `load_role`, and asserts the model id, the four declarable limits, the output-contract name, the ceiling, and the registry columns the compiler reads — `tools` and `pool_classes`. It also drives one malformed record through the real `load_role` and asserts refusal, because the criteria that say *fails to load* are otherwise decided only on the decode seam. Without it a column the migration spells one way and the loader reads another way passes both the schema check and every offline loader criterion, and the first observation is a step failing at compile time in production.

Every other criterion runs in the offline gate. **The loader ones are fed a record, and the seam that takes one is `decode_role_record(role_record, integration_records)`** — `load_role(role_name, version)` opens its own query and cannot be handed a record, so it queries and then calls the decode seam, which is where the record-shape refusals live and what the offline criteria call directly.

**Stub coverage:** AC-0202 and AC-0220 carry validated red stubs; AC-0238 and AC-0250 carry `no stub (implementation-discovered)` with the discovery predicate T3 records; T1 and T4 carry `no stub (goal-based)` and map to no criterion. Every other criterion in this spec grows from the AC-0202 or AC-0220 surface.

No criterion here calls a provider, so this spec needs no cloud credential and
carries no spend. **This contract deliberately ships a runtime in which no tool
body ever executes**, because AC-0233 refuses every call until the successor
spec's predicate arrives. AC-0202's stack is therefore asserted by construction
and never demonstrated end-to-end here; the first tool body to run anywhere does so under
`walking-skeleton-authority-containment`.

**A note on what the suite cannot see.** The quarantine criteria assert that
free text does not cross a boundary this system builds. Several limits stay open,
all of them r8's and none closed by anything here.

**No Phase 1 role can hold a `free-text` integration**, and [ADR-0006](../../adr/0006-four-r5-deviations-for-phase-1.md) D3 owns the reasoning: deriving role class from an empty ceiling narrows r5 § 4's quarantine-only exemption to unreachable, so the trust-class layer's free-text branch ships unexercised. That is the safe posture and it is deliberate; it also means the quarantine criteria establish the *admitted-types* path only. D3 stopped being provisional when `role-configuration-seams` was ratified on 2026-09-21.

No structural defence has been tested under an unlimited adaptive budget. The
guarantee is "no attacker-authored free *text*", **not** "no attacker-influenced
signal" — r8's first accepted limit names selection influence explicitly. And
the reference-selection channel stays *unmitigated and unmeasured*: a closed
vocabulary bounds the alphabet, not the channel, so a quarantined agent can pass
signal into a planning agent's context by which references it chooses, and
resolution detects forged references rather than steered-but-valid ones. AC-0238 pins minting order and set immutability, which makes forgery
unrepresentable; it says nothing about steering, and adding it raises rather
than lowers the odds a reader takes reference integrity as solved.

**Compiling a role**

- [x] **AC-0201.** No tool is reachable outside the wrapped stack. The constructed `Agent` holds exactly one toolset besides the framework's own `_AgentFunctionToolset`, and it is the decision point; a decorator-registered tool and a second entry in `toolsets=[…]` each fail the build. r5 § 2 R5 makes both invariants members of the structural catalogue, and AC-0202 cannot absorb them because it roots its walk at `CompiledRole.stack` and so never sees the `Agent`.
- [x] **AC-0260.** Compiling a role fails when a binding does not resolve: a `ceiling` entry naming an integration the compiler was not given, and a `tool_name` absent from that integration's `tools`. Both are compile errors, not denials at call time.
- [x] **AC-0202.** Every compiled agent's toolset chain is exactly the policy decision point wrapping the step-event toolset wrapping the trust-class toolset wrapping the function toolset, asserted by walking `CompiledRole.stack` and traversing `WrapperToolset.wrapped`; and the compiler's structural check rejects a hand-built chain composed in any other order. The walk roots at `.stack` and not on the `Agent`, which carries its own `_AgentFunctionToolset` alongside anything passed.
- [x] **AC-0203.** Compiling any non-quarantined role — one whose `ceiling` is non-empty — bound to an integration whose `integration_registry.trust_class` is `free-text` fails at compile time.
- [x] **AC-0204.** The **resolved request parameters** a stub model receives from a compiled agent carry `thinking` as `False`, and compiling a role declaring any other value fails. The observation is at the model boundary, not on the carrier: a compiler that computes the value and constructs the `Agent` without it is otherwise green while the provider reasons. Omitting the key is not sufficient either — an omitted value leaves `ModelRequestParameters.thinking` at its `None` default, which is the provider's default and not a disabled one. **The observation point is the resolved parameters rather than the settings mapping**, because on the pinned 2.45.0 `Model.prepare_request` resolves the unified `thinking` setting into `ModelRequestParameters.thinking` and strips the key from the settings the model's `request` receives. It carries the value across when the profile declares `supports_thinking` **or** `thinking_always_enabled`, except that an explicit `False` is dropped on an always-thinking profile — a framework capability limit on models that cannot stop reasoning, unreachable on the Anthropic-on-Bedrock path Phase 1 pins, and carried as a Follow-on below because refusing a role bound to such a profile would be a new control rather than a wording fix.
- [x] **AC-0205.** A compiled quarantined role carries a tool-retry budget of zero and an output-validation-retry budget of zero, and a malformed structured output raises with the stub model's request count at one — the re-prompt over untrusted text is the behaviour the budgets exist to stop, so it is asserted and not only implied.
- [x] **AC-0206.** Compiling a role whose `model_settings.limits` declares any of the four integer keys wider than the `PoolConfig` default fails the build; a narrower value compiles to its own; a key the role omits inherits the pool's. A role may narrow and never widen, and `count_tokens_before_request` is pool-owned, so a role declaring it fails.
- [x] **AC-0251.** Compiling a role whose `model_settings.model_id` is absent from `PoolConfig.allowed_model_ids` fails the build, and a role omitting `model_id` fails to load.
- [x] **AC-0269.** Compiling a role whose `model_settings.settings` carries a key outside the declared set fails. On the pinned 2.45.0 `ModelSettings` is a `total=False` TypedDict of sixteen keys including `extra_headers` and `extra_body`, so a compiler that forwards the role's `settings` dict unchecked lets role data set arbitrary provider headers and request bodies — authority no ratified document assigns it, reaching past the `Model` seam r8 relies on for portability. AC-0204 pins one key's value; this pins the key set.
- [x] **AC-0258.** Compiling a role fails when any integration its `ceiling` binds does not list the role's `pool_class` in `integration_registry.pool_classes`, an empty list meaning available to every class. A role whose `pool_class` is absent matches only integrations whose `pool_classes` is empty.
- [x] **AC-0219.** A role is quarantined exactly when its `ceiling` is empty, and a compiled quarantined role carries no domain tools on its stack and the `reference-selection` output type. Both are read from the compiled agent, not the record. The derivation is guarded in **both** directions: an empty-ceiling role declaring any `output_schema_ref` other than `reference-selection` fails to compile, and so does a role declaring `reference-selection` whose `ceiling` is non-empty — otherwise one ceiling entry silently promotes the quarantined role to a planning role, restoring the retry budgets AC-0205 exists to hold over attacker-authored text.
- [x] **AC-0267.** Compiling a role whose `output_schema_ref` is absent from the compiler's declared set fails. Membership is enforced where the set is created rather than per member as members are added: AC-0219 guards only the two quarantined pairings, so without this a non-quarantined role declaring an unrecognised name is refused by nothing here — including `free-form`, which [`walking-skeleton-step-lifecycle`](../walking-skeleton-step-lifecycle/spec.md)'s AC-0255 adds as the set's third member with a guard scoped to quarantined roles only. A permissive member is the one way a planning role could obtain an unparsed `str`. **Refusing a permissive *member* on a non-quarantined role is a different rule and is not this criterion's:** it belongs to the spec that adds the member, since AC-0255's guard there is scoped to quarantined roles only. This criterion's case is therefore pinned to a name no named successor adds.
- [x] **AC-0273.** An `integration_registry` row whose `tools` value is absent, `null`, not an array, or an empty array fails to load, naming the row — **every row the registry read returns, not only the rows a role binds.** The ratified design states the rule unqualified and has `list_integration_tools()` span every row rather than the bound subset, so a guard scoped to bound rows would leave the defect this criterion cites open. The ratified design makes the column nullable with no default precisely so "the omission is visible where it happens", and no other criterion carries that rule: AC-0260's case is a `tool_name` missing *from* `tools`, a compile error that never fires for a row contributing no tools at all. The consequence lands on AC-0233, which enumerates every tool in the registry through `list_integration_tools()` — a row whose `tools` is null contributes nothing, so that criterion passes over a shrunken universe while asserting it covered the registry.
- [x] **AC-0266.** A role record binding an integration whose `integration_registry.trust_class` is not a member of r5 § 4's closed set fails to load, naming the value. AC-0203 refuses the single literal `free-text` on a non-quarantined role, which is a denylist: every other non-member — a casing variant, a typo, an invented name — compiles onto a planning role and reaches a `TrustClassToolset` branch no criterion decides. The shipped column is `text NOT NULL` with no CHECK and this spec's migration adds none, so the membership test is the loader's, and it fails closed.

- [x] **AC-0265.** A pool configuration whose `CED_POOL_DEFAULT_LIMITS` omits or nulls any of the four integer keys fails `verify_boot`, naming the key. Three of the four `UsageLimits` fields default to `None`, which is unlimited, so a present-and-parsing JSON object can still leave a limit unset — and AC-0206 only compares a role against the pool, never the pool against itself.
- [x] **AC-0270.** `verify_boot` fails when `CED_POOL_DEFAULT_LIMITS` sets `count_tokens_before_request` to anything other than `false`. [ADR-0006](../../adr/0006-four-r5-deviations-for-phase-1.md) § Confirmation assigns this deployment predicate to this spec so D1's mitigation is checked rather than remembered. Both directions matter: absent, AC-0246's pre-request bound is inert in production; present, every invocation breaks on an IAM shape ADR-0006 records as not re-derived.
- [x] **AC-0261.** A compile refusal is observable from the event log: the executor appends a `step.failed` event whose `type` distinguishes it from a runtime fault and whose `agent_role` names the role that failed to compile, and a refusal the loader raises is appended at its own stage rather than as a step fault. An operator reading the log can tell a bad role file from a runtime fault without attaching a debugger. **Which guard refused is deliberately not asserted here:** the `events` envelope migration 0001 ships carries no column for it, this spec writes no payload object, and adding either would amend a table the foundation spec owns. That half is a Follow-on below, owned by the spec that opens the payload-object write path.
- [x] **AC-0262.** A role record whose `ceiling` is absent, `null`, or any JSON value other than an array fails to load. `[]` is the canonical empty ceiling, and role class is derived from that emptiness, so a loader that coerces a malformed value to empty would silently reclassify an analysis role as quarantined.

**Bounding cost before the call**

- [x] **AC-0246.** A compiled agent whose `model_settings.limits.per_request_input_tokens_limit` is below the counted tokens raises `UsageLimitExceeded` before the model's request is issued, demonstrated with a stub model that implements `count_tokens` and records whether `request` ran. The bound is per request and denominated in tokens; `input_tokens_limit` is cumulative across a run and cannot bound one request.

**Refusing before the predicate arrives**

- [x] **AC-0233.** With no containment predicate installed, a call is refused and no tool body executes for every role in the role registry and every tool in the integration registry, enumerated by reading `agent_role` and `integration_registry` through `list_roles()` and `list_integration_tools()` rather than from a list held in the suite. **The enumeration is non-empty and covers the skeleton's named roles**, and at least one pair reaches the decision point and is recorded as refused *there*, distinctly from a pair refused earlier at resolution — otherwise an implementation in which every role fails an earlier guard satisfies the criterion without the decision point being wired at all.
- [x] **AC-0234.** A refusal raised by the decision point is an instance of the interval's own declared refusal type, and is neither `ModelRetry` nor any subclass of it. Pinning the type positively is what separates a refusal from a crash: a bare exclusion is satisfied by an `AttributeError` from an unwired decision point.
- [x] **AC-0259.** A refusal raised by the decision point propagates out of `Agent.run` rather than being caught and returned to the model, and no further model turn is issued after it, observed on the stub model's request count.

**Holding the quarantine boundary**

- [x] **AC-0220.** Output from an integration whose `trust_class` is `admitted-types` that is neither a closed-vocabulary label nor a typed scalar is refused by the runtime's deterministic parser, called directly and outside any agent, so the refusal cannot come from the framework's structured output.
- [x] **AC-0268.** A closed-vocabulary label the runtime's declared vocabulary does not contain is refused by the parser, even when it is well formed. That vocabulary is a compile-time constant of the runtime, defined in one place a reviewer can see change, and is not derived from a role record, a registry row or model output. r5 § 4 admits labels because for a label the shape *is* membership in a finite fixed alphabet; a parser whose label test is a token-shape regex satisfies AC-0220 while letting the filer steer hyphenated tokens drawn from the filing across into a planning agent. AC-0221 gives references their provenance guard; this gives labels theirs.
- [x] **AC-0274.** Three clauses. A typed scalar whose type is not one of the declared admitted scalar types is refused by the parser. Where an admitted scalar type is itself an enumeration, a non-member of that enumeration is refused too, and **that enumeration's members are declared in the same place and under the same rule as the label vocabulary** — otherwise the membership test is an inline literal at the call site and is not reviewable the way AC-0268 requires for labels. And **Phase 1 mints no content-addressing value, so the parser refuses every one of them here** — this spec writes no payload object, and `<owner_scope>/<content_hash>` is the key format `walking-skeleton-step-lifecycle` introduces, so there is no minted locator for a provenance test to admit. The rule that survives the phase is the general one: **any admitted value that addresses stored content carries AC-0221's minting-and-provenance test, whichever class a ratified document files it under**, and the spec that adds a minting source adds that criterion. Stating the blanket refusal rather than the provenance test is what makes this clause testable now: a refusal-only case cannot distinguish a provenance check from a categorical one, and there is no admitted direction here to pair it with. The declared type set lives beside the label vocabulary AC-0268 pins, under the same rule: one place a reviewer can see change, not derived from a role record, a registry row or model output. **The governing set is r8 § 4's**, which this spec's obligation table already names as the owner of the quarantine guarantee, and it differs from r5 § 4's — r5 gives "decimals, dates, enumerated units", r8 adds content-addressed locators. **The third clause is why that difference is safe to resolve in r8's favour.** r8 files a content-addressed locator as a scalar and not a reference, so a type-admission test alone would let the quarantined agent emit a well-formed `<owner_scope>/<content_hash>` key the runtime never minted — contradicting r8 § 4's own "the model cannot emit an identifier the pipeline did not mint", and relocating the channel rather than closing it. Keying the clause on *behaviour* — addressing stored content — rather than on which class a document files a value under also reaches any content-addressing type either document adds later. Without this, typed scalars are the one admitted class with no declared membership: AC-0220's only refusal case is free prose, which every candidate scalar encoding rejects anyway, so an opaque locator string or an unbounded unit token is admitted by a green suite. With references closed on provenance and labels closed on membership, this is the widest remaining channel out of the quarantined agent.
- [x] **AC-0221.** A reference the runtime did not mint for the current candidate set is refused by the parser, including one that is well-formed and resolvable in another set. Shape validity is not provenance.
- [x] **AC-0238.** The candidate reference set is complete before the quarantined agent's first model turn, and the set observed before that turn is **non-empty, equal to a recorded expected set committed beside the fixture**, and identical to the set observed after the last turn. The expectation is a committed artifact rather than a second call to the pipeline under test: an expectation computed from that pipeline cannot fail for a pipeline that derives the wrong set from the fixture, and a committed one makes every change to the derived set a reviewable diff. Without the non-emptiness a mint that produces nothing satisfies both clauses. Both snapshots are taken by the test's stub model at its own request boundary, so the ordering is decided outside the implementation.
- [x] **AC-0250.** A mutation of the candidate reference set attempted while the agent run is in flight raises the runtime's own refusal and leaves the set unchanged, asserted on both. The set is per-step in-process state, so the refusal is asserted in process and not against a store; naming the observable is what separates a built guard from an incidental `TypeError`.

- eugenelim, register entry on `src/ced/domain/quarantine/mint.py`, **closed 2026-09-22 outside this spec**: *a duplicated identity attribute on a numeric fact resolved last-wins, under no recorded rule.* `dict(attrs)` in the mint's reader kept the final occurrence, so `name="A" name="B"` minted `B` where an XML-conformant XBRL processor rejects the document — a lenient HTML reader as the minting authority could therefore disagree with the strict resolver a successor spec will write, on input the filer controls.
